# Generated FastMCP comparison

`fastmcp-input-schemas.json` is generated by importing the reference bridge and
calling its actual FastMCP `list_tools()`. It is not inferred from Python AST or
annotations. The snapshot records the source commit, file SHA-256 and MCP version.
The reference import and schema listing do not connect to an emulator.

To regenerate, use an isolated Python environment with `mcp==1.30.0` installed:

```sh
/path/to/venv/bin/python scripts/export-reference-schema.py /path/to/ares-64/tools/mcp/ares_mcp.py > tests/reference/fastmcp-input-schemas.json
npm run build
node scripts/schema-parity.cjs > tests/reference/schema-parity-report.json
node --test tests/schema-parity.test.cjs
```

Run these commands from `tools/electron-spike`. The Node comparison launches the
actual stdio registry using an unused metadata path; no Electron/native instance
or ROM is needed. Normal tests compare that registry to the checked-in report.
Regenerate only after reviewing changes; the snapshot does not approve scope
removal or establish behavioral/result parity.

The full comparison ignores documentation (`title`, `description`, `$schema`) and
irrelevant ordering of schema unions, enums, required fields and object keys. It
preserves validation bounds, defaults, nullability, object unknown-field policy,
nested structures and tuple order. The separate signature projection compares
parameter names, required fields, primitive types, nullability and defaults; it
intentionally excludes bounds and nested validation.

Current evidence: 68 names in both registries; no missing/extra tools. 67 signatures
match. `batch.max_seconds` defaults to 20 in Electron versus 60 in the reference;
Electron's bounded batch implementation currently caps at 20 seconds. All 68 full
schemas differ, including Electron's strict unknown-field rejection. Further
validation differences are explicit in the report, including resource limits and
more specific object/enum schemas. These remain visible task 9 compatibility
limitations, not an assertion of full schema parity. The report says nothing
about result shapes or game/manual acceptance.
